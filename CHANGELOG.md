# Changelog

## Unreleased

### Changed
- **`pastMatchesFor` renamed `otherMatchesFor`** (Phase 2 review): it also lists later-dated rows of the merchant, so the question reads "Aplicar às outras N transações?". Spec v1 §5 and §8.2 and plan T09 follow.
- **Category deletion impact and undo; safer seeding and restore** (Phase 2 review): pure `deletionImpact(categories, transactions, rules, id)` counts the transactions and rules a deletion touches and lists the subcategories going with it, for the confirmation. `commitCategoryDeletion` also returns `undo` (its stamp and every changed record as it was), and `undoCategoryDeletion(db, undo)` writes them back with a new stamp in one transaction, or nothing if any was written after the deletion (`updatedAt` and `updatedBy` compared), a restored subcategory's parent is gone, or a sibling took the name. Seeding skips a default whose name a live sibling already has (`nameKey`, shared with `createCategory`), with what hangs from it. Restore no longer validates the pattern of a tombstoned rule and checks references between live records: a subcategory's parent is a live top-level category, a rule targets a live subcategory, a transaction's category is live (`data.rules[i].categoryId must be a live subcategory`). Spec v1 §5 and §7 follow.
- **Safer rules, better default order, pinned learned patterns** (Phase 2 review): `validateRule` rejects a regex with a nested quantifier such as `(a+)+` (`Rule pattern has a nested quantifier`), and rules test at most `MAX_MATCHED_MERCHANT_LENGTH` (200) characters of the merchant. `ruleMatcher` skips a stored rule that fails to compile and lists it in `.invalid` instead of throwing, so one bad synced rule never blocks an import; plan T16 validates incoming rules. Default rules: "Uber Eats" → Delivery (not Apps de corrida), "Drogaria Delivery" → Farmácia (Delivery matches brands only), "Bar Claro" → Bares (not Telefonia); fictitious fixture rows added. [ADR 013](docs/adr/013-derived-data-migrations.md) extends ADR 009's derived-data rule to learned rule patterns, merchants and shipped defaults; a test pins `learnedRulePattern` for fixed merchants through the adapter. Spec v1 §4 and §5 follow (the rule editor defaults to `contains`).
- **Duplicate learned rules collapse** (Phase 2 review): when several user rules share a merchant's pattern (two devices offline, a restore), `recategorize` updates the first by priority then id and returns the others in `deletedRuleIds`; `commitRecategorization` tombstones them in the same transaction and returns them. Rule order is `byPriorityThenId` in `src/categorize/rules.ts`, shared with the matcher. Spec v1 §5 follows.
- **Defaults always seeded before an import; rules can run again** (Phase 2 review): `commitImport` seeds the missing default categories and rules (`planSeed` in `src/storage/categories.ts`, the same rule as `seedDefaults`) inside its own transaction, so an import never runs without them; opening the app still writes nothing. When seeding adds rules, a live uncategorized row gets a category only when a seeded rule wins over all live rules (a learned rule answered "no" still outranks it), in the same transaction. New pure `recategorizeAll(rows, rules)` (non-manual rows whose category changes) and `commitRecategorizeAll(db)`, the explicit "apply the rules again", in one transaction with one stamp. `isLive` moved to `src/storage/db.ts` (still exported from `repository.ts`). Spec v1 §5 and §8.1 follow.
- **Previews behind Cloudflare Access** ([docs/setup.md](docs/setup.md#put-cloudflare-access-in-front-of-the-previews)): how the owner turns on Cloudflare Access for the preview URLs of both Workers, with a policy for their own e-mail, while production stays open; how to check it. A manual dashboard step; CI is unchanged.
- **React replaces Preact** in the T01 shell ([ADR 010](docs/adr/010-react-replaces-preact.md)): `src/main.tsx` mounts with `createRoot` under `StrictMode`, `vite.config.ts` uses `@vitejs/plugin-react`, `tsconfig.json` uses the default `react-jsx` runtime. Dependencies: `react`, `react-dom`, `@vitejs/plugin-react`, `@testing-library/react`, `@testing-library/dom`, `@types/react`, `@types/react-dom` in; `preact`, `@preact/preset-vite`, `@testing-library/preact` out. The shell test renders with React. Diagrams regenerated ("React UI" tile), README badge, CONTRIBUTING and the project agents updated.
- **Plan revision** (before T08): each person runs their own instance, one owner per deploy, and end-to-end encrypted sync (Worker + D1 behind Cloudflare Access with the owner's e-mail, recovery key) is part of every deploy and comes before the screens ([ADR 011](docs/adr/011-self-hosted-instances-with-mandatory-e2e-sync.md), supersedes ADR 001 and the automatic backup file of ADR 008; export stays optional). React replaces Preact ([ADR 010](docs/adr/010-react-replaces-preact.md)). The assistant is Claude Code commands outside the app, `/organizar` and `/investir`; the app calls no AI API ([ADR 012](docs/adr/012-assistant-as-claude-code-commands.md)). [docs/plan.md](docs/plan.md) has the new order: Phase 2 categorization (T08–T09: wider, editable tree; learning asks before touching past rows), Phase 3 analysis (T10–T12: statement and month periods, editable 50/30/20, limits per category with 80%/100% warnings, spike insight at +30% and R$ 50), Phase 4 cloud (T13–T16), Phase 5 assistant (T17–T18), Phase 6 navigable prototype approved before any screen (T19), Phase 7 screens (T20–T26, with a mid-phase review after T23), Phase 8 PWA and quality (T27–T29, install invite after the first import, reminder only at statement close), then demo v1. Code review now runs at every phase close and before merging sensitive PRs (storage, backup, sync, crypto, security). [Spec v1](docs/spec/v1.md) adds periods, `limits` and `plans` stores, `budgetSplit` and `thresholds` settings, the editable tree and the records `/organizar` writes; the PRD, AGENTS.md, ARCHITECTURE.md, SECURITY.md, README ("Run your own instance") and [docs/setup.md](docs/setup.md) follow, and references to the old task numbers are updated. The untracked review snapshot `docs/plan-review.md` was deleted.
- **Plan** (Phase 1 review): T07's `persist()` bullet now says the helper is ready and that calling it at app open and keeping the result moved to T13 (open, together with `openDatabase`'s `onBlocked` warning) and T18 (display). T23 lists two open points for the sync ADR: splitting settings into device-local and synced (`statementClosingDay`, `monthlyIncomeCents` synced), and a wipe/epoch rule so the server doesn't resurrect data after delete all or restore. T24–T26 follow ADR 009 (server sees `updatedBy`; cursor is the highest `updatedAt` pushed; LWW by `(updatedAt, updatedBy)`). T15 says `dismissed` holds one record per occurrence.
- **Import: one statement, cleaner merchants** (Phase 1 review): `ParsedRow.statementIdFrom` says where the statement id came from (`fileName`, `closingDay` or the provisional `latestDate`). `dedupe` returns `matchedIds` (stored rows the file matched; `StoredTransaction` now has `id` and `statementId`) and `moveToStatement`, and `commitImport(db, { record, transactions, moveToStatement }, clock)` moves those rows to the new file's statement in the same transaction, so a partial export followed by the closed statement leaves one statement (spec v1 §4 step 5). The Nubank file name also matches the browser copy suffix (`Nubank_2026-11-11 (1).csv`). The merchant collapses internal whitespace. `parseBrlAmount` accepts any whitespace after the sign, no-break space included; `formatBrl` splits cents with `(abs - abs % 100) / 100`. Spec §4 notes that changing fingerprint normalization needs a migration recomputing stored fingerprints.
- **Backup restore** (Phase 1 review): restore accepts any `schemaVersion` up to the app's and runs per-version record upgraders (`backupUpgraders`, empty for now; `upgradeBackupData`); a newer backup is rejected with "update the app first". Every record is validated with the domain's rules (`Number.isSafeInteger` cents, `parseIsoDate` dates, `TRANSACTION_KINDS` and other enums, installment shape, ISO `updatedAt`/`deletedAt?`, known setting keys and values), e.g. `Invalid backup: data.transactions[0].amountCents must be an integer number of cents (got 12.5)`. Device-local settings (`deviceId`, `lastStampAt`, `lastSyncAt`, `backupFileHandle`) are no longer exported and are kept on restore; `lastStampAt` moves up to the newest restored `updatedAt`. Fictitious v1 backup fixture in `test/fixtures/backup-v1.json`.
- **Sync clock and record identity** ([ADR 009](docs/adr/009-sync-clock-and-record-identity.md), Phase 1 review): `dismissed` holds one record per deleted occurrence, `{ id, fingerprint, dismissedAt }`, keyed by a random `id` and indexed by `fingerprint` (a fingerprint is never a key); `dedupe` takes one `{ fingerprint }` per dismissed occurrence. Every write is stamped once per IndexedDB transaction with `updatedAt = max(now, lastStampAt + 1 ms)` (`lastStampAt` saved in `settings` in the same transaction) and `updatedBy = deviceId` (created on first write if missing), so `changedSince` misses nothing written in the same millisecond or after the clock goes back. `remove` reads and writes in one transaction, and removing a tombstone is a no-op. `openDatabase` closes its connection when another tab opens a newer version and reports `onBlocked` when an upgrade waits on a tab that doesn't close. The migration test now upgrades through a synthetic next step. Migration v1 was edited in place: no user data exists yet.
- **Data durability** ([ADR 008](docs/adr/008-data-durability-local-first-sync-ready.md)): imported months must never disappear. v1 stays local and adds persistent storage with a visible status, an install prompt (iOS home screen apps escape Safari's 7-day deletion) and automatic backup (a file rewritten after each change on Chrome/Edge desktop, a download reminder elsewhere). T07 now builds sync-ready storage: repositories, `updatedAt`, tombstones (`deletedAt`), `deviceId`; the backup includes `dismissed`. The [plan](docs/plan.md) maps Phase 6 (v2), T23–T27: end-to-end encrypted sync between devices on Cloudflare (Worker, D1, Access), free for one user.

- **Docs** (phase 0 review): [docs/setup.md](docs/setup.md) says fork PRs get no test report comment (read-only token) and that `pr-<N>` previews stay public after the PR closes, with how to take them down. [ADR 004](docs/adr/004-cloudflare-workers-static-assets-hosting.md) and [SECURITY.md](SECURITY.md) name both deploy secrets (API token and account ID).
- **Test report comment** (`scripts/test-report.ts`) stays under GitHub's 65,536-character limit (budget 60,000): when the full linked list does not fit it drops the links, then lists only tests that did not pass, then omits the list, and as a last resort keeps as many failures as fit. Test names and errors are collapsed to one line, Markdown and HTML characters are escaped and `<!--` / `-->` are stripped, so a test name can no longer break the table or the history block. `todo` tests are counted in the header, so it adds up to "All N tests".
- **Privacy guard** catches more statement formats: `.csv`, `.ofx`, `.qfx`, `.qif`, `.pdf`, `.xls`, `.xlsx`, `.ods`, `.zip` and compressed variants (`.csv.gz`, `.ofx.bz2`, ...), any case, still allowed under `test/fixtures/`. On PRs it also checks every file added by any PR commit, so a statement added and then deleted cannot slip into history. `.gitignore` lists the new extensions, and `tsconfig.json` now typechecks `scripts/`.
- **CI hardening**: Cloudflare secrets are scoped to the steps that run Wrangler, never to `npm ci`, the build or the tests. PR code runs in the `test` job with a read-only token; a separate `report` job holds `pull-requests: write`, runs the base branch's `scripts/test-report.ts` on the `test` job's artifact and only updates a test report comment written by `github-actions[bot]`. PRs are tested at their head commit, so the report's line links match. The `deploy` job reuses the `test` job's Vitest UI report instead of running the tests a second time after the app is live.

### Added
- **Recategorization in storage** (T09, part 2): `commitRecategorization(db, id, categoryId, applyPast, clock)` in `src/storage/categories.ts` writes the transaction as manual, the learned rule (created or updated) and, only with the user's yes, the past transactions of that merchant, in one IndexedDB transaction with one stamp; an unknown or deleted transaction, or a category that isn't a live subcategory, writes nothing. `commitImport` now categorizes the new transactions with the live stored rules in the same transaction, so after a correction the next import of that merchant comes categorized. Spec v1 §8.1 and §8.2 follow.
- **Learning from corrections** (T09, part 1, [ADR 007](docs/adr/007-editable-rules-for-categorization-without-ai.md)): `src/categorize/learn.ts` with `recategorize(transaction, categoryId, rules)`, which makes the transaction manual and returns a user rule matching exactly its normalized merchant (`learnedRulePattern`: anchored, escaped regex, so "Padaria Exemplo" never catches "Padaria Exemplo Filial") at `LEARNED_RULE_PRIORITY` 100, above every default, updating the existing rule for that merchant instead of duplicating it; `pastMatchesFor(transaction, categoryId, transactions)`, the past transactions the question "Apply to N?" would change (live, same merchant, not manual, not already in the category); and `applyToPast`, which sets them with `categorySource: 'rule'`. A test runs the fixture import after a correction and gets the merchant categorized.
- **Category storage** (T08, part 3): `src/storage/categories.ts` with `seedDefaults(db, clock)`, which writes each default category and rule whose fixed id isn't stored (live or tombstone) in one transaction with one stamp, so edits and deletions of defaults survive (a default under a deleted category is skipped), and `commitCategoryDeletion(db, id, target, clock)`, which reads the live records and writes `deleteCategory`'s result (tombstones for the deleted categories and rules, moved transactions and rules) in one IndexedDB transaction, or nothing on an invalid id or target. Restore rejects a rule whose pattern fails `validateRule` (`data.rules[i].pattern must be a valid rule pattern`). Plan T13 gets an open point: seeding on a new device versus edits of defaults on another.
- **Editable categories** (T08, part 2): `src/categorize/edit.ts` with `createCategory` (random UUID, trimmed non-blank name unique among siblings ignoring case and accents, two levels only), `renameCategory` and `deleteCategory(categories, transactions, rules, id, target)`, which deletes a category (with its subcategories if top-level) and returns the transactions and rules to move to the target subcategory, or, with `UNCATEGORIZED`, the transactions without a category and the rule ids to delete, so nothing points to a deleted category. Defaults are editable the same way.
- **Categories and rules** (T08, part 1, [ADR 007](docs/adr/007-editable-rules-for-categorization-without-ai.md)): `src/categorize/tree.ts` with the default two-level tree in pt-BR (12 categories, 35 subcategories) under fixed UUIDs (`defaultId`), so devices seeding defaults never duplicate them; `src/categorize/rules.ts` with `validateRule` (blank pattern, non-integer priority and invalid regex fail at creation), `ruleMatcher` (ascending priority, ties by id, first match wins) and `categorize` (sets `categorySource: 'rule'`, leaves no match Uncategorized, skips manual rows); `src/categorize/default-rules.ts` with regex rules for common Brazilian merchants from priority 1000. `normalizeMerchant` moved to `src/domain/merchant.ts`, shared by dedupe and rules. Fictitious fixture `test/fixtures/categorize-merchants.csv`.
- **Storage** (T07, [ADR 003](docs/adr/003-indexeddb-for-storage.md), [ADR 008](docs/adr/008-data-durability-local-first-sync-ready.md)): `src/storage/` on `idb`, database `card-insights`, stores `transactions`, `imports`, `rules`, `categories`, `settings` and `dismissed` (keyed by `fingerprint`), indexes on `transactions.statementId`, `.fingerprint`, `.date` and `updatedAt` on every synced store. Ordered migrations (`migrations[n]` upgrades version `n` to `n + 1`; `SCHEMA_VERSION` is their count) run in `upgrade`. `createRepository(db, store, clock)` gives `get`, `list`, `put` (stamps `updatedAt`), `remove` (tombstone: sets `deletedAt`; an unknown key throws) and `changedSince(timestamp)` (tombstones included); `get` and `list` skip tombstones. `commitImport` saves an import's transactions and its record in one IndexedDB transaction. `getSetting`/`setSetting` and `ensureDeviceId` (random UUID, created once). `exportBackup` writes `{ app, schemaVersion, exportedAt, data }` with every store and tombstone; `restoreBackup` validates the envelope, version and each record's key (`Invalid backup: data.rules[0] has no id`) and replaces everything in one transaction, so a restored backup exports identically; `deleteAllData` clears every store. `requestPersistentStorage` reports `granted`, `denied` or `unsupported`. `Category` and `Rule` types in `src/domain/category.ts`. Tests use `fake-indexeddb`.
- **Import dedupe** (T06): `src/import/dedupe.ts` with `fingerprint` (`date|merchant|amountCents|n/total` or `-`; the merchant is compared case-, accent- and spacing-insensitively) and `dedupe(rows, stored, dismissed)`, which counts occurrences per fingerprint over the stored transactions within the file's date range and adds `max(0, inFile − stored − dismissed)`. A new fingerprint whose `date + amountCents` matches a stored row with another merchant is added with status `review`. Returns the rows to add (with `fingerprint` and `status`) and `ImportSummary { added, existing, review }`, three disjoint counts that add up to the file's rows. Pure: storage passes stored transactions and dismissed counts in (T07).
- **Nubank card CSV adapter** (T05): `src/import/types.ts` with `ImportAdapter`, `ParsedRow`, `ImportFile` and `ImportMeta` (spec v1 §3.1); `src/import/csv.ts`, a small CSV reader (quoted fields with commas, `""` escapes, BOM, CRLF, blank lines skipped, errors name the line); `src/import/adapters/nubank-card-csv.ts`, detected by the exact header `date,title,amount`. It extracts `Parcela n/N` into `installment` and strips it from `merchant`, strips acquirer markers (`Mlp*`, `Wl *`, `Dl*`, `Htm*`, `Pg *`, `I*Vmt*Cielo`) while `rawTitle` stays untouched, sets `kind` (`Pagamento recebido` → payment, `IOF…`/`Juros…` → fee, other negatives → refund, else purchase) and `statementId` (from `Nubank_YYYY-MM-DD.csv`, else the next closing date on or after the latest row using `statementClosingDay`, else the latest row date). An invalid row throws `Line N: <reason>`; nothing is dropped. `daysInMonth` is now exported from `src/domain/date.ts`. Fictitious fixtures in `test/fixtures/`.
- **Money and dates** (T04): `src/domain/money.ts` with `parseBrlAmount` (pt-BR string to integer cents with string math, optional sign and spaces, `.` thousands groups, exactly two decimals; anything else throws `Invalid BRL amount: "<input>"`) and `formatBrl` (Intl pt-BR, fed a decimal string so no float division; output pinned in tests, including the no-break space). `src/domain/date.ts` with `parseIsoDate`, which validates a calendar `YYYY-MM-DD` without `Date`, so no time zone shift. `src/domain/transaction.ts` with the `Transaction`, `TransactionKind` and `Installment` types from spec v1 §2.

Every PR commit uploads an app preview (`pr-<N>` alias) and the Vitest UI report (a separate `card-insights-tests` Worker, `reports.wrangler.jsonc`); the sticky test report comment, now rendered by `scripts/test-report.ts`, links both and keeps a per-commit history. `scripts/preview-urls.ts` reads the preview URLs from Wrangler's output, so no `workers.dev` subdomain is hardcoded. A `privacy-guard` job runs `scripts/check-data-files.ts` on `git ls-files` and fails if any `.csv`, `.ofx` or `.pdf` (any case) is tracked outside `test/fixtures/`.
