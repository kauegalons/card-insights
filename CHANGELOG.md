# Changelog

## Unreleased

### Changed
- **Sync clock and record identity** ([ADR 009](docs/adr/009-sync-clock-and-record-identity.md), Phase 1 review): `dismissed` holds one record per deleted occurrence, `{ id, fingerprint, dismissedAt }`, keyed by a random `id` and indexed by `fingerprint` (a fingerprint is never a key); `dedupe` takes one `{ fingerprint }` per dismissed occurrence. Every write is stamped once per IndexedDB transaction with `updatedAt = max(now, lastStampAt + 1 ms)` (`lastStampAt` saved in `settings` in the same transaction) and `updatedBy = deviceId` (created on first write if missing), so `changedSince` misses nothing written in the same millisecond or after the clock goes back. `remove` reads and writes in one transaction, and removing a tombstone is a no-op. `openDatabase` closes its connection when another tab opens a newer version and reports `onBlocked` when an upgrade waits on a tab that doesn't close. The migration test now upgrades through a synthetic next step. Migration v1 was edited in place: no user data exists yet.
- **Data durability** ([ADR 008](docs/adr/008-data-durability-local-first-sync-ready.md)): imported months must never disappear. v1 stays local and adds persistent storage with a visible status, an install prompt (iOS home screen apps escape Safari's 7-day deletion) and automatic backup (a file rewritten after each change on Chrome/Edge desktop, a download reminder elsewhere). T07 now builds sync-ready storage: repositories, `updatedAt`, tombstones (`deletedAt`), `deviceId`; the backup includes `dismissed`. The [plan](docs/plan.md) maps Phase 6 (v2), T23–T27: end-to-end encrypted sync between devices on Cloudflare (Worker, D1, Access), free for one user.
- **Architecture diagrams**: the Mermaid charts in [README.md](README.md) and [ARCHITECTURE.md](ARCHITECTURE.md) are replaced by drawn images: a high-level design (`docs/assets/hld-light.png`: laptop and phone, the browser with the Preact UI, the import and rules core and IndexedDB, and Cloudflare only serving static files), the v1 module map (`docs/architecture/v1.png`) and the CI and deploy flow (`docs/architecture/flows/deploy.png`). `docs/architecture/draw.py` writes them as SVG and PNG (Python 3 and headless Chrome or Edge); ARCHITECTURE.md explains how to regenerate them. Style derived from YudiG12/second-brain-mcp (MIT).
- **Docs** (phase 0 review): [docs/setup.md](docs/setup.md) says fork PRs get no test report comment (read-only token) and that `pr-<N>` previews stay public after the PR closes, with how to take them down. [ADR 004](docs/adr/004-cloudflare-workers-static-assets-hosting.md) and [SECURITY.md](SECURITY.md) name both deploy secrets (API token and account ID).
- **Test report comment** (`scripts/test-report.ts`) stays under GitHub's 65,536-character limit (budget 60,000): when the full linked list does not fit it drops the links, then lists only tests that did not pass, then omits the list, and as a last resort keeps as many failures as fit. Test names and errors are collapsed to one line, Markdown and HTML characters are escaped and `<!--` / `-->` are stripped, so a test name can no longer break the table or the history block. `todo` tests are counted in the header, so it adds up to "All N tests".
- **Privacy guard** catches more statement formats: `.csv`, `.ofx`, `.qfx`, `.qif`, `.pdf`, `.xls`, `.xlsx`, `.ods`, `.zip` and compressed variants (`.csv.gz`, `.ofx.bz2`, ...), any case, still allowed under `test/fixtures/`. On PRs it also checks every file added by any PR commit, so a statement added and then deleted cannot slip into history. `.gitignore` lists the new extensions, and `tsconfig.json` now typechecks `scripts/`.
- **CI hardening**: Cloudflare secrets are scoped to the steps that run Wrangler, never to `npm ci`, the build or the tests. PR code runs in the `test` job with a read-only token; a separate `report` job holds `pull-requests: write`, runs the base branch's `scripts/test-report.ts` on the `test` job's artifact and only updates a test report comment written by `github-actions[bot]`. PRs are tested at their head commit, so the report's line links match. The `deploy` job reuses the `test` job's Vitest UI report instead of running the tests a second time after the app is live.

### Added
- **Storage** (T07, [ADR 003](docs/adr/003-indexeddb-for-storage.md), [ADR 008](docs/adr/008-data-durability-local-first-sync-ready.md)): `src/storage/` on `idb`, database `card-insights`, stores `transactions`, `imports`, `rules`, `categories`, `settings` and `dismissed` (keyed by `fingerprint`), indexes on `transactions.statementId`, `.fingerprint`, `.date` and `updatedAt` on every synced store. Ordered migrations (`migrations[n]` upgrades version `n` to `n + 1`; `SCHEMA_VERSION` is their count) run in `upgrade`. `createRepository(db, store, clock)` gives `get`, `list`, `put` (stamps `updatedAt`), `remove` (tombstone: sets `deletedAt`; an unknown key throws) and `changedSince(timestamp)` (tombstones included); `get` and `list` skip tombstones. `commitImport` saves an import's transactions and its record in one IndexedDB transaction. `getSetting`/`setSetting` and `ensureDeviceId` (random UUID, created once). `exportBackup` writes `{ app, schemaVersion, exportedAt, data }` with every store and tombstone; `restoreBackup` validates the envelope, version and each record's key (`Invalid backup: data.rules[0] has no id`) and replaces everything in one transaction, so a restored backup exports identically; `deleteAllData` clears every store. `requestPersistentStorage` reports `granted`, `denied` or `unsupported`. `Category` and `Rule` types in `src/domain/category.ts`. Tests use `fake-indexeddb`.
- **Import dedupe** (T06): `src/import/dedupe.ts` with `fingerprint` (`date|merchant|amountCents|n/total` or `-`; the merchant is compared case-, accent- and spacing-insensitively) and `dedupe(rows, stored, dismissed)`, which counts occurrences per fingerprint over the stored transactions within the file's date range and adds `max(0, inFile − stored − dismissed)`. A new fingerprint whose `date + amountCents` matches a stored row with another merchant is added with status `review`. Returns the rows to add (with `fingerprint` and `status`) and `ImportSummary { added, existing, review }`, three disjoint counts that add up to the file's rows. Pure: storage passes stored transactions and dismissed counts in (T07).
- **Nubank card CSV adapter** (T05): `src/import/types.ts` with `ImportAdapter`, `ParsedRow`, `ImportFile` and `ImportMeta` (spec v1 §3.1); `src/import/csv.ts`, a small CSV reader (quoted fields with commas, `""` escapes, BOM, CRLF, blank lines skipped, errors name the line); `src/import/adapters/nubank-card-csv.ts`, detected by the exact header `date,title,amount`. It extracts `Parcela n/N` into `installment` and strips it from `merchant`, strips acquirer markers (`Mlp*`, `Wl *`, `Dl*`, `Htm*`, `Pg *`, `I*Vmt*Cielo`) while `rawTitle` stays untouched, sets `kind` (`Pagamento recebido` → payment, `IOF…`/`Juros…` → fee, other negatives → refund, else purchase) and `statementId` (from `Nubank_YYYY-MM-DD.csv`, else the next closing date on or after the latest row using `statementClosingDay`, else the latest row date). An invalid row throws `Line N: <reason>`; nothing is dropped. `daysInMonth` is now exported from `src/domain/date.ts`. Fictitious fixtures in `test/fixtures/`.
- **Money and dates** (T04): `src/domain/money.ts` with `parseBrlAmount` (pt-BR string to integer cents with string math, optional sign and spaces, `.` thousands groups, exactly two decimals; anything else throws `Invalid BRL amount: "<input>"`) and `formatBrl` (Intl pt-BR, fed a decimal string so no float division; output pinned in tests, including the no-break space). `src/domain/date.ts` with `parseIsoDate`, which validates a calendar `YYYY-MM-DD` without `Date`, so no time zone shift. `src/domain/transaction.ts` with the `Transaction`, `TransactionKind` and `Installment` types from spec v1 §2.
- **Deploy** (T03): `wrangler.jsonc` serves `dist/` with Cloudflare Workers Static Assets (SPA fallback to `index.html`, no Worker script). A `deploy` job in CI runs on every push to `main` after `test` and `privacy-guard`, one at a time, and deploys both the app and the Vitest UI report, so the first merge creates both Workers. Every PR commit uploads an app preview (`pr-<N>` alias) and the Vitest UI report (a separate `card-insights-tests` Worker, `reports.wrangler.jsonc`); the sticky test report comment, now rendered by `scripts/test-report.ts`, links both and keeps a per-commit history. `scripts/preview-urls.ts` reads the preview URLs from Wrangler's output, so no `workers.dev` subdomain is hardcoded. [docs/setup.md](docs/setup.md) explains how to deploy your own.
- **CI** (T02): `.github/workflows/ci.yml` runs `npm ci`, `typecheck`, `test` and `build` on every PR and on push to `main` (Node from `.nvmrc`), and keeps one sticky test report comment on the PR. A `privacy-guard` job runs `scripts/check-data-files.ts` on `git ls-files` and fails if any `.csv`, `.ofx` or `.pdf` (any case) is tracked outside `test/fixtures/`.
- **Scaffold** (T01): Vite + Preact + TypeScript `strict`, Vitest with the Vitest UI and happy-dom, `.nvmrc` (Node 24), scripts `dev`, `build`, `preview`, `typecheck`, `test`, `test:ui`, and the `src/` and `test/fixtures/` layout.
- **Foundation docs** (T00): [PRD v1](docs/prd/v1.md), [spec v1](docs/spec/v1.md), [architecture](ARCHITECTURE.md), the [build plan](docs/plan.md) and ADRs [001](docs/adr/001-static-app-without-backend.md) to [007](docs/adr/007-editable-rules-for-categorization-without-ai.md): a static app with no backend, Preact + Vite + TypeScript strict, IndexedDB, Cloudflare Workers Static Assets, money in integer cents, dedupe by fingerprint and occurrence count, categorization by editable rules.
- **Transaction deletion** planned in T15, with a `dismissed` store so re-imports respect it.
- **Rules for contributors and agents**: [AGENTS.md](AGENTS.md) (tests first, no real data, English names), [CONTRIBUTING.md](CONTRIBUTING.md), [SECURITY.md](SECURITY.md) with the privacy model, and project agents in `.claude/agents/` for development, tests and clean-context review.
- A `.gitignore` that keeps statements (`*.csv`, `*.ofx`, `*.pdf`) out of the repository, except fictitious fixtures in `test/fixtures/`.
